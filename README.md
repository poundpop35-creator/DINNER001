# RU Study Planner

แอปช่วยเรียนภาษาไทย: บทเรียน สมุดจด แบบฝึกทบทวน แผนการเรียน และปฏิทิน

## การทำงาน

- ลงชื่อเข้าใช้ก่อนเปิดพื้นที่เรียนส่วนตัว
- เก็บโน้ต ความคืบหน้า คำตอบ และการปรับแผนใน Supabase ตามบัญชี
- สมุดจดรองรับหัวข้อ รายการ ตัวหนา สีตัวอักษร ไฮไลต์ รูปภาพ ค้นหา แท็ก และคำถามทบทวน
- อัปโหลดรูปเข้า private Storage ก่อนแทรกลงโน้ต รองรับ JPG/PNG/WebP/GIF ไม่เกิน 5 MB ต่อรูป
- แสดงสถานะบันทึกออนไลน์ทุกหน้า และยืนยันว่าบันทึกสำเร็จเมื่อฐานข้อมูลตอบกลับแล้ว
- เปิดจากเครื่องอื่นด้วยบัญชีเดียวกันเพื่ออ่านข้อมูลชุดเดียวกัน
- ถ้าเน็ตหลุด เก็บคิวชั่วคราวและลองส่งใหม่เมื่อเชื่อมต่อได้ ตรวจ revision เพื่อป้องกันการเขียนทับจากอีกเครื่อง
- ส่งออกและนำเข้าไฟล์สำรองโน้ตพร้อมรูป รวมถึงพิมพ์โน้ตเป็น PDF ผ่านเบราว์เซอร์
- แยกปฏิทินบรรยายกับสอบ มีตัวกรองและลิงก์แหล่งอ้างอิง

## แหล่งเรียนของมหาวิทยาลัย

- [RU Course on Demand](https://ondemand.ru.ac.th/) — วิดีโอคำบรรยายย้อนหลัง ใช้บัญชี RU e-Service
- [RU Cyber Classroom](https://cyberclassroom.ru.ac.th/) — ถ่ายทอดตามตารางบรรยาย
- [ร้านหนังสือรามคำแหง](https://bookstore.ru.ac.th/) — ค้นตำราด้วยรหัสวิชา

ระบบของมหาวิทยาลัยและบัญชีในแอปนี้เป็นคนละระบบ ความพร้อมของคลิปและประกาศผู้สอนต้องตรวจจากมหาวิทยาลัย

## เริ่มพัฒนา

Frontend เป็น static app ใน `dist/` ใช้ hash routing ใช้ Quill และ Supabase JS แบบตรึงรุ่นและเก็บ browser assets ใน repository

```sh
npm run check
npm test
python3 -m http.server 8080 --directory dist
```

`vercel.json` ระบุ build check และโฟลเดอร์ `dist/` สำหรับ deployment ส่วน GitHub Actions ตรวจ syntax และ tests ก่อนเผยแพร่

## ตั้งค่า Supabase Auth

เจ้าของโปรเจ็กต์ต้องเปิดผู้ให้บริการเข้าสู่ระบบก่อนใช้งาน:

1. กำหนด Site URL และ Redirect URLs ให้ตรงกับ URL หน้าแอป
2. หากใช้ Google ให้ตั้ง Client ID / Client Secret ใน Supabase Authentication ไม่ใส่ secret ใน frontend หรือ Git
3. Authorized Redirect URI ของ Google ใช้ `https://<project-ref>.supabase.co/auth/v1/callback`
4. หากใช้อีเมล ให้ตรวจการยืนยันอีเมลและการส่งอีเมลของโปรเจ็กต์
5. กลับมาโหลดหน้าแอปใหม่ ปุ่ม Google เปิดตามสถานะ provider จริง

หน้า “บัญชีออนไลน์” แสดงวิธีตั้งค่าตาม origin ที่กำลังใช้งาน

## ความเป็นส่วนตัวและข้อมูล

ตาราง workspace และรูปส่วนตัวมี Row Level Security ตรวจเจ้าของด้วย Supabase Auth ฝั่งเว็บใช้ publishable key เท่านั้น ห้ามใส่ service role หรือ secret key ใน client

ค่าความคืบหน้าถูกส่งขณะใช้งานด้วยบัญชีที่เข้าสู่ระบบ ไม่ฝังข้อมูลส่วนตัวใหม่ลงใน source code แคชในเครื่องใช้ลดการโหลดและพักงานเมื่อเครือข่ายขัดข้อง ไม่ใช่ที่เก็บข้อมูลหลัก

เนื้อหาบทเรียนและลิงก์ต้นฉบับอ่านจาก catalog API แยกจาก workspace ส่วนตัว ตารางของภาคใหม่ต้องอัปเดตจากมหาวิทยาลัย ไม่คัดลอกวันสอบของภาคเก่าไปใช้

## การตรวจรุ่นนี้

ผ่านการทดสอบอัตโนมัติ 55 รายการ รวมการจำลองสองอุปกรณ์ที่ไม่แชร์แคช การโหลดรูปจากบัญชีเดียวกัน เครือข่ายขัดข้อง พื้นที่เครื่องเต็ม และ revision conflict

การจำลองสองอุปกรณ์ใช้ test API ไม่ใช่การลงชื่อเข้าใช้ด้วยบัญชีจริง ยังต้องตรวจ Google Login และการใช้งาน editor บนอุปกรณ์จริงหลังเจ้าของตั้งค่า Auth
